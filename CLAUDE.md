# CLAUDE.md

Guidance for Claude Code (and other AI agents) working in this repo.

## Project

A tiny **local, OpenAI- and Anthropic-compatible rotation proxy**.
chicco fronts a pool of providers behind one stable endpoint, forwarding
`/v1/chat/completions` and `/v1/messages` and rotating/failing over between
providers. Go, with `cmd/`, `internal/` and a Helm `chart/`.
(*chicco* is Roman colloquial for "bro".)

## Commands

```sh
make help         # every verb this repo exposes
make build        # Compile the binary into ./bin
make docker-build # Build the chicco:latest image (see docs/DOCKER.md to run it)
make install      # go install into GOBIN
make lint         # Run golangci-lint (falls back to go vet)
make run          # Run chicco (pass args with ARGS="...")
make snapshot     # Build a local unpublished release with GoReleaser
make test         # Run tests with the race detector
make clean        # remove build artifacts
```

## Tooling

- `make setup` installs the pre-commit hook, and that is the whole of it.
  Don't add a `.githooks/` directory: `core.hooksPath` replaces `.git/hooks/`
  wholesale, so setting it silently stops every pre-commit hook from running.
- Hooks are pinned by commit SHA with the tag in a trailing comment. A tag can
  be moved, a SHA cannot.
- CI runs this same `.pre-commit-config.yaml` through `pre-commit/action`, so
  what passes locally is what gates the pull request.

## Conventions

- Match existing style; don't reformat unrelated code.
- Conventional Commits for messages (see CONTRIBUTING.md) — they drive the
  release-please version bump.
- `CHANGELOG.md` is generated by release-please; don't edit it by hand.
- Update `docs/` and `examples/` with behavior changes.
- Never commit secrets; CI runs gitleaks. Keep `.env` out of git.

## Guardrails

- Prefer the standard library; a new module needs a reason.
- Wire-compatibility with the OpenAI and Anthropic schemas is the contract —
  never 'improve' a response shape.
- Provider API keys pass through; they are never logged, cached or persisted.
- Failover must be transparent to the caller: same status codes, same stream
  framing.
- Don't touch generated files or lockfiles by hand.
- Ask before large refactors or destructive operations.
